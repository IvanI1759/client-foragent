# Product Context

## 4 ИИ-агента

### 1. Маркетолог (`marketer.js`)
Анализирует рынок, целевую аудиторию, конкурентов. Помогает строить стратегию продвижения.
Использует RAG: загруженные документы с анализами рынка, портретами ЦА, кейсами.

### 2. Копирайтер (`copywriter.js`)
Пишет тексты для постов, лендингов, email-рассылок, презентаций.
Использует RAG: примеры текстов, tone of voice, брендбук.

### 3. Рекламщик (`ads.js`)
Создаёт рекламные объявления для таргета, контекста, Telegram Ads.
Использует RAG: примеры успешных объявлений, таргетинги, бюджеты.

### 4. Упаковщик (`packager.js`)
Формулирует офферы, УТП, структуру продуктовых страниц.
Использует RAG: существующие офферы, описания продуктов, отзывы клиентов.

## Система доступа

- **Владелец** (OWNER_CHAT_ID в .env): полный доступ + `/grant`, `/revoke`, `/upload`, `/users`, `/status`
- **Партнёры** (таблица `access_list`): доступ к агентам и выбранной базе знаний
- **Все остальные**: отказ с показом user_id

Авторизация проверяется в `auth.js` middleware ДО любого handler.

## RAG Pipeline

```
Документ → парсинг (PDF/DOCX/TXT) → чанки (500 токенов, overlap 50)
→ Gemini Embedding API → vector(768) → Supabase pgvector
```

При запросе пользователя:
```
Вопрос → embedding → cosine similarity search (top-3, score >= 0.7) → контекст + промпт → Gemini → ответ
```

Документы привязаны к `agent_type` — каждый агент ищет только в своей базе знаний.

## UX-модель

- Inline-клавиатура для выбора агента
- Текстовые сообщения для общения с агентом
- Команда `/switch` для смены агента
- Контекст сессии сохраняется в таблице `sessions`
