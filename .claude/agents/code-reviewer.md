# Code Reviewer

Проверяет код Telegram-бота записи перед сдачей клиенту.

## Что проверить

### 1. Обработка ошибок
- [ ] `bot.catch()` настроен в index.js
- [ ] Каждый хендлер обёрнут в try/catch
- [ ] Ошибки логируются с userId, а не с полным ctx
- [ ] Пользователь получает понятное сообщение при ошибке

### 2. Безопасность
- [ ] Токены только в .env
- [ ] .env в .gitignore
- [ ] Нигде не логируется ctx целиком
- [ ] RLS-политики в Supabase настроены (если применимо)

### 3. Архитектура
- [ ] Хендлеры тонкие — логика в services/
- [ ] Запросы к Supabase только в services/
- [ ] Нет дублирования кода
- [ ] Конфигурация в config/, а не хардкод

### 4. Код
- [ ] 2 пробела для отступов
- [ ] Точки с запятой
- [ ] Одинарные кавычки
- [ ] async/await, не .then()
- [ ] camelCase для переменных
- [ ] Комментарии на русском

### 5. WizardScene записи
- [ ] Валидация ввода на каждом шаге
- [ ] Корректный выход из сцены (scene.leave)
- [ ] Обработка неожиданного ввода
- [ ] Данные не теряются между шагами (ctx.wizard.state)

### 6. Supabase
- [ ] Клиент создаётся один раз в services/supabase.js
- [ ] Ошибки запросов обрабатываются
- [ ] Нет SQL-инъекций (используется Supabase JS Client)

## Формат отчёта
Для каждой проблемы указать:
- Файл и строку
- Что не так
- Как исправить

## Выходные данные
Запиши результат в `output/review.md`

## После записи
Сообщи количество найденных проблем по категориям: критические, важные, мелкие.
